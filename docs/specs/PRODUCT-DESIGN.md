## 1. 产品定位

### 1.1 一句话定位

**一个用自然语言驱动的浏览器**——你说"打开百度，搜索金证，把前五条结果的
摘要整理给我"，浏览器自己看页面、自己点、自己填、自己总结，并且**越用越
熟练**（记住成功的操作脚本，下次直接复用）。

这句话拆成五个用户可感知的动作，是后续全部需求与指标的锚点。五动作构成
执行闭环：**你说**（输入目标）→ **它看 / 它做 / 它证**（一轮执行周期）→
**它学**（跨会话沉淀）：

| 动作 | 含义 | 反面（不是） |
|---|---|---|
| **你说** | 用自然语言提出目标，无需学习命令语法 | 不是 CDP/Playwright 式 API 调用 |
| **它看** | 每回合基于真实页面状态（状态块）行动，不靠模型记忆 | 不是"记住的 HTML 快照" |
| **它做** | 在真实渲染引擎内执行点/填/总结等真实浏览器操作 | 不是爬虫式静态抓取 |
| **它证** | 每步附截图/思考/观察，失败给出结构化原因 | 不是黑盒"成功/失败" |
| **它学** | 成功脚本入库复用，重复任务越来越快 | 不是每次从头推理 |

一句话定位的反例（避免的方向）："能聊天的浏览器插件"、"带 AI 的 RPA 工具"、
"自动写代码的抓包器"——这些都不是本产品的卖点，详见 §1.4 与 §2.3。

### 1.2 边界与同类差异

产品处在三个已知品类之间的空白：

- **对传统浏览器**（Chrome/Firefox/WebKit）：不替代日常上网，只接管"明确目标、
  多步、重复"的任务执行，把浏览器当作可编程的执行器。
- **对爬虫/抓取工具**（requests + BeautifulSoup 类）：基于 WPE WebKit **完整
  渲染**，能处理登录态、JS 重渲染、验证码前置页等真实环境；输出不限于 HTML，
  而是截图、可核对的操作轨迹。
- **对通用 AI Agent 框架**（纯 LLM + 工具调用）：动作执行落在真实浏览器内核
  内、脚本可记忆复用、会话可崩溃恢复，是"能干活"而不是"能聊天"。

### 1.3 四大差异化主张

每条主张 = 定义 + 架构对齐 + 竞品对比 + 对应指标（映射到 §6）。

#### 主张①：真浏览器，不是爬虫

- **定义**：核心动作基于 WPE WebKit 完整渲染引擎执行，页面在真实引擎中加载、
  渲染、执行 JS。遇到登录态、SPA 重渲染、验证码前置页等真实环境，产品能力
  不塌方。
- **架构对齐**：`webai-webkit` 承担 FFI 与页面事件；所有动作用 JS 表达，经
  单一 JavaScriptCore 执行（架构定论三），页面 bundle 在 `document-start`
  注入。
- **竞品对比**：爬虫工具在"页面被 JS 重渲染后才出现的内容"上失效；本产品
  与用户亲眼所见一致。
- **对应指标**：标准操作用例矩阵通过率 ≥95%（§6 正确性）。

#### 主张②：越用越快（脚本记忆复用）

- **定义**：用户或脚本完成过的成功操作自动沉淀为可复用脚本；相似任务再次
  出现时直接回放已验证脚本、只换参数，跳过大部分 LLM 推理，时延与 token
  消耗显著下降。
- **架构对齐**：两阶段参数化脚本（架构定论二）+ 脚本记忆与自修复（架构
  定论四）：条目 `task/verb/url/script`，tag `script:{verb}`；回放失败触发
  **一次**带上下文的 LLM 修复并更新记忆；`script_memory_enabled` 可关闭。
- **竞品对比**：一次性 Agent 每次从头推理；本产品"第二次就快"。
- **对应指标**：记忆命中时重复任务 LLM 调用 ≤ 首次的 30%；统计口径见
  §6 M-2（包含 planning 与 repair 调用、采样 ≥30 个任务、按中位数口径）。（§6 效率）

#### 主张③：可观察、可恢复

- **定义**：每一步都有 thought（模型在想什么）/ observation（页面返回了什么）/
  screenshot（页面长什么样）三件套，用户随时可核对"AI 到底点在了哪"；进程
  崩溃后从 JSONL 会话日志续跑，不丢会话。
- **架构对齐**：会话一等公民 + JSONL 追加持久化（架构定论五）：写后即 flush，
  崩溃最多损失最后一条截断记录，恢复时跳过截断行续跑（`~/.webai/sessions/`）。
  失败结构化为 execute/verify 阶段 + JS 异常原文（架构定论二），禁止
  `unknown error`。
- **竞品对比**：黑盒 Agent 无法回答"为什么失败"；本产品把诊断项摆上台面。
- **对应指标**：崩溃后会话恢复成功率 100%；失败调用 100% 结构化（§6 健壮性、
  可诊断）。

#### 主张④：本地优先、可嵌入

- **定义**：核心为单二进制本地运行，不依赖云端 Agent 服务；通过标准 ACP
  （Agent Communication Protocol，JSON-RPC over WebSocket / 行分隔 TCP）
  对外提供 browser agent 能力，编辑器、脚本、任意宿主均可嵌入。
- **架构对齐**：`bins/webai` 单二进制，默认 TUI、`--serve` 起 ACP、`--headless`
  纯脚本；`webai-acp` crate 实现协议与会话注册。
- **竞品对比**：云端浏览器 Agent 上送数据、依赖网络；本产品数据不出本机，
  且可编程接入任意工作流。
- **对应指标**：单会话空闲内存 <300MB（不含 LLM）（§6 资源）。

### 1.4 差异化的优先级与取舍

- **v1 主打**：主张①真浏览器 + 主张②越用越快，二者是"能干活的浏览器内核"
  与"说句话就办成事"的直接载体（对应版本规划 v0.1、v0.2）。
- **v1 支撑**：主张③可观察可恢复是"能干活"的可信前提，主张④可嵌入是
  "脚本开发者"使用方式的通道。
- **明确不投入**：为主张②的记忆复用，允许接受首次执行略慢（要沉淀脚本）；
  为主张③的可恢复，优先保证 JSONL 转录完整性而非 UI 花哨。

## 2. 目标用户与场景

### 2.1 用户-场景矩阵

「交付物/接入方式」一列是区分相近用户的关键判据：**开发者/极客**把浏览器
能力当作**自用工具**内嵌进自己的脚本/CI/内部系统（接入即产品本身）；
**脚本开发者**把**浏览器任务脚本**本身作为交付物（可版本化、可对外交付，
接入是手段而非目的）。

| 用户 | 典型场景 | 交付物/接入方式 | 关键诉求 | 频率 | 付费/活跃信号 |
|---|---|---|---|---|---|
| 信息工作者 | 多站信息搜集、日报汇总（如 sina 财经新闻聚合） | 对话即用，无代码（TUI） | 准确、可核对（带截图） | 每日 | 日报产出率、核对满意度 |
| 开发者/极客 | 把浏览器当 API 用，嵌入自己的工作流 | 自用接入：内嵌进自己脚本/CI/内部系统，ACP session 级调用 | ACP/HTTP 接口、可编程 | 每周 | 接口调用量、脚本数 |
| 脚本开发者 | 通过 ACP 接口将浏览器能力产品化为可复用脚本 | 脚本交付物：以"任务脚本"为交付物，可版本化/对外供给 | 协议稳定、可编程、可恢复 | 每周 | SDK/协议使用数、故障自助率 |
| 自动化运维 | 定期巡检网页、下载报表 | 长期驻留：`--serve` 常驻 + 定时调度 | 脚本复用、稳定、无人值守恢复 | 每日/定时 | 无人值守完成率、恢复成功率 |

### 2.2 每类用户细化

#### 信息工作者

- **画像**：运营、分析师、编辑。目标不是技术，而是"把信息拿到手"。
- **诉求拆解**：①答案要准（来源可核对）；②操作要可回溯（截图证明点到了）；
  ③重复汇总要快（脚本记忆复用）；④不折腾系统（本地单二进制）。
- **边界**：只做"搜集+整理+下载"，不做文档生产（其本职仍由人完成）。
- **失败容忍度**：低。任何一步错了要能看到在哪错、为什么错。

#### 开发者/极客

- **画像**：把浏览器能力当工具拼进自己的脚本/CI/内部系统的人。
- **诉求拆解**：①程序化调用（ACP JSON-RPC）；②会话与上下文可控
  （session/new → prompt → close）；③出错可编程处理（结构化 error.code）；
  ④本机数据私有。
- **边界**：不是完整的浏览器 API 库，只承诺 browser agent 能力面（13 动词 +
  snapshot/下载）。
- **判据（与脚本开发者区分）**：接入即产品——浏览器能力作为用户自己系统
  的组成部分被内嵌，不独立交付。
- **失败容忍度**：中，但要求错误可归因、可重试。

#### 脚本开发者

- **画像**：以"浏览器任务脚本"为交付物的人，可能是本产品的重度外部集成方。
- **诉求拆解**：①协议稳定（接口面不轻易 breaking）；②脚本可复用、可版本化；
  ③恢复语义明确（崩溃后从哪续）。
- **边界**：脚本由用户自己的 LLM/宿主编排，本产品提供执行与记忆，不提供
  可视化编排。
- **判据（与开发者/极客区分）**：交付即产品——"任务脚本"本身是用户对外
  交付或长期维护的资产，接入只是手段。
- **失败容忍度**：中，要求脚本失败后可一键修复重试。

#### 自动化运维

- **画像**：巡检网页可用性、定时抓下载报表、监控页面状态变更。
- **诉求拆解**：①无人值守（崩溃恢复、不进死循环）；②脚本复用 + 稳定
  （同一巡检逻辑长期跑）；③资源可控（内存、步数守卫）。
- **边界**：不替代监控平台，只提供"定时任务里的浏览器执行器"。
- **失败容忍度**：高（可重跑），但要求"要么成功要么结构化失败"，严禁静默。

### 2.3 非目标（v1 明确不做）

| 非目标 | 原因 | 何时可能做（v1 之外） |
|---|---|---|
| 普通用户日常上网替代品 | 日常浏览追求速度与手感，与"任务执行器"定位冲突；浏览器已有成熟生态 | 不计划 |
| 可视化拖拽 RPA 编辑器 | 面向非技术用户的重型编排，超出单二进制定位且与"脚本可编程"诉求重复 | 视第三方生态需求再评估 |
| 跨设备同步账号体系 | 云同步与多端账号违背本地优先；账号/登录态属于用户自有 | 若有团队场景需求，以 ACP 服务化方案评估 |

**非目标的原则**：一切会削弱"本地优先、可嵌入、越用越快"这一定位的功能，
v1 一律不做；边界上出现的机会（如团队版记忆库）应在 ACP 能力面之上平滑演进，
而不是并进 v1 内核。

### 2.4 v1 目标用户优先级

四类用户按"接入方式 → 优先级"排序，分组不合并，判据沿用 §2.1 矩阵的
「交付物/接入方式」列：

- **第一优先**：开发者/极客 与 脚本开发者——同属"程序化接入"阵营（最大交集
  是 ACP 接口），但交付物不同（自用接入 vs 脚本交付物），前者是最早的验证者、
  后者是"把浏览器当 API 用"假设的直接付款方。
- **第二优先**：自动化运维——脚本复用、无人值守恢复与主张③完全对齐，
  是高价值低摩擦场景。
- **第三优先**：信息工作者——需要 TUI 完整体验成熟后（v0.3）才能服务好；
  前期通过**早期内测席位**收集反馈，不提前承诺完整服务。

## 3. 产品形态定义

产品的三种形态共享同一内核：**会话一等公民**（架构定论五）——无论从哪个
形态接入，背后都是同一个 `AgentSession`（转录 + JSONL 持久化 + 记忆句柄），
同一套 `AgentLoop`（计划-行动-观察）。形态只负责"接入方式"与"表现层"，
不承担任何业务逻辑，保证三种形态行为一致、可互测。

### 3.1 形态一：本地 TUI 对话式浏览器（主形态）

**定位**：普通用户与信息工作者的默认入口，"打开就能用"的第一形态。

- **技术底座**：`webai-tui` crate（ratatui），`bins/webai` 默认即进入该形态。
- **入口**：`$ webai` 启动即进入终端对话界面。
- **交互约定**（v1 固定，作为验收基线）：
  | 键位 | 行为 |
  |---|---|
  | `Enter` | 发送当前输入 |
  | `↑` / `↓` | 滚动历史转录 |
  | `PgUp` / `PgDn` | 翻页 |
  | `Esc` | 清空当前输入；**输入为空时**按 Esc 退出程序 |
  | `Ctrl+C` | 退出 |
- **流式呈现**：每步实时流式显示三元组——
  `thought`（模型在想什么）/ `observation`（页面返回了什么）/ `screenshot`
  （页面长什么样）；模型产出过程中的中间步骤（navigate → click → ...）逐条
  追加，不让用户等待"完成后一次性出结果"。
- **截图内联**：
  - 终端支持 Kitty / iTerm2 / Sixel 图协议时：截图原地内联渲染，所见即所得。
  - 不支持时：显示占位符 `[截图 640×480 @ /path/to/xxx.png]`（尺寸 + 路径），
    用户可自行打开核对。
- **自动附带截图**：每个成功浏览器操作完成后，自动把该步截图追加到转录尾部，
  用户可随时核对"AI 到底点在了哪"（对应主张③）。
- **验收基线**：旅程 A（首次使用）完整可演示；交互约定逐条可测（见 §5 旅程 A、
  §6 指标）。

### 3.2 形态二：ACP 智能体服务

**定位**：程序化接入形态，面向开发者/极客、脚本开发者——把浏览器能力当 API 用。

- **协议**：标准 ACP（Agent Communication Protocol），JSON-RPC
  **over WebSocket** 与 **行分隔 TCP**（`\n` 分隔的 JSON 行）两种传输，
  由 `webai-acp` crate 实现。
- **会话生命周期**（对齐架构定论五）：
  ```
  session/new →  session/prompt*（可多次） →  session/close
  ```
  - `session/new`：创建独立浏览器上下文与转录，返回 `session_id`。
  - `session/prompt`：提交自然语言指令，**流式**返回步骤与结果事件
    （`SessionEvent::Step / Done / Error`，含截图与 `reused_script` 标记）。
  - `session/close`：释放上下文与转录句柄。
- **会话隔离**：每个 session 独立浏览器上下文与转录，互不影响；崩溃时该会话
  可从其转录恢复（同一 JSONL 机制）。
- **事件契约**：需要在协议层面显式暴露 `Step/Done/Error` 事件，宿主无需
  解析聊天文案。
- **验收基线**：旅程 D（脚本接入）可演示；协议级序列化往返测试覆盖
  （见 §6 可诊断指标与架构测试金字塔）。

### 3.3 形态三：HTTP/脚本接入（服务模式）

**定位**：`webai --serve` 以 ACP 服务进程常驻，供任意脚本/宿主通过
JSON-RPC 调用，是把形态二部署到生产使用的形态。

- **入口**：`webai --serve [--bind <addr>] [--public]`。
- **网络默认**：默认仅绑定 `127.0.0.1`（本机安全默认）。
- **公网暴露**：
  - 必须显式开启（`--public` 或配置绑定到非 loopback 地址）；
  - 必须启用**配对认证**（配对码式 handshake）后方可接受客户端，
    防止匿名接入执行任意浏览器操作。
- **认证密钥**：不与产品命令收集路径耦合，隔离存于配置/环境，见 §7 配置章节。
- **验收基线**：默认绑定未配置公网地址时，来自非 loopback 的连接必须被拒；
  公网模式未配对即拒绝（对应 §6 安全指标 0 例越权）。

### 3.4 三种形态的关系与选择

| 接入方式 | 使用对象 | 一句话差异 | 对应形态 |
|---|---|---|---|
| 终端对话 | 信息工作者、普通用户 | 人直接对着浏览器说话 | 形态一 TUI |
| 协议调用 | 开发者、脚本开发者 | 程序替人说，浏览器照做 | 形态二 ACP |
| 常驻服务 | 自动化运维、集成方 | 服务在跑，脚本随时调 | 形态三 `--serve` |

**一致性约束**：三形态共用 AgentSession/AgentLoop；任何形态下产生的行为差异
一律视为缺陷（架构测试金字塔含 host 集成层，三形态可同套夹具覆盖）。

## 4. 核心功能规格（FR-1~FR-8）

> 每条 FR 采用统一规格格式：**需求描述 / 触发与输入 / 行为规格（正常路径）/
> 边界与异常 / 验收标准（可测）**。验收标准直接喂给测试（§6 指标 + 架构
> 测试金字塔），不允许出现"体验良好""合理性能"类模糊表述。

### FR-1 自然语言驱动浏览

**需求描述**：以自然语言指令驱动真实浏览器完成动作序列，是产品的第一能力。

**触发与输入**：任意自然语言句子，可能包含 1 或多个浏览器动作意图。

**行为规格**：
1. 支持 13 个浏览器动词，映射到两阶段 JS 脚本（架构定论一）：
   `navigate` / `click` / `fill` / `hover` / `drag` / `press_key` /
   `evaluate` / `screenshot` / `accessibility_tree` / `get_text` /
   `get_html` / `download` / `snapshot`。
2. **自动拆解**：检测到 ≥2 个动作动词，或出现连接词（`然后`/`再`/`接着`/
   `and then`/`then`），自动要求模型先产出 `create_plan`（计划），再逐步执行。
   - 计划经用户可见（TUI 流式展示），不静默跳过。
3. **状态块注入**：每回合开始自动注入当前浏览器状态块
   `{ url, title, readyState, body_excerpt }`，保证模型基于真实页面行动而非
   记忆；状态块在模型不可读取前不得先行（无状态块的回合不允许动作决策）。

**边界与异常**：
- 单动词指令（如"打开 github.com"）不强制拆计划，直达执行。
- 计划与执行之间页面状态变化：以每回合实时状态块为准重估。
- 动作文档失真（e.g. 找不到元素）→ 进入 FR-3 修复路径，禁止当场报
  `unknown error`。

**验收标准**：
- [ ] 13 个动词各有可执行的两阶段脚本固化条目（`execute_<verb>` + `verify_<verb>`）。
- [ ] 对 20 条含多动作指令的用例，`create_plan` 触发率 100%，且计划先于任何执行动作出现。
- [ ] 状态块注入：连续 100 回合抽样，每回合模型输入中 url/title/readyState 均非空且与真实页面一致。
- [ ] 动词表外操作返回结构化错误（错误码 + 可读信息），不吞成 unknown error。

### FR-2 可视化执行过程

**需求描述**：每一步执行对用户完全透明——看得到"在想什么、页面返回了什么、
页面长什么样"，失败时看到确切原因。

**行为规格**：
1. 每步三元组：`thought`（模型思考）/ `observation`（页面观察）/
   `screenshot`（页面截图），三者在 TUI 流式逐条呈现（§3.1）。
2. 每回合成败均结构化：
   - 成功：observation + 自动截图（动作后触发，供核对）。
   - 失败：结构化错误，包含**阶段**（`execute` 或 `verify`）+ **JS 异常原文**，
     界面不得出现"未知错误"/empty error。

**边界与异常**：截图失败（引擎异常）时仍给出 observation 与占位符，但产品
不得因截图失败而丢弃本轮结果。

**验收标准**：
- [ ] 成功路径：每个浏览器操作后转录尾部必含一条截图记录（或明确占位符+原因）。
- [ ] 失败路径：100% 错误带 `phase ∈ {execute, verify}` 且含 JS 异常原文；
      全量错误日志中 `unknown error`/`unknown` 出现次数 = 0。
- [ ] 错误断言唯一：协议层 `error.code` 面（§6 可诊断指标）无裸字符串兜底。

### FR-3 脚本记忆与复用

**需求描述**：成功操作沉淀、相似任务复用、失败自愈，让产品"越用越快"
（支持主张②）。

**行为规格**：
1. **入库**：成功浏览器操作以结构化条目入库
   `{ task, verb, url, script }`，tag `script:{verb}`（架构定论四）。
2. **回放**：相似任务再次出现时，优先回放记忆脚本；界面/事件显式标记
   `[复用了记忆脚本 navigate→extract]`（TUI 文本、ACP 事件 `reused_script`）。
3. **修复**：回放或新脚本失败时，触发**一次**带上下文的 LLM 修复；上下文固定
   为：失败脚本 + JS 异常原文 + ≤3 条相似脚本 + 浏览器状态快照 + 页面文本。
   - 修复成功 → 更新记忆条目；修复再次失败 → 结构化错误返回 AgentLoop 决策
     （换路径或求助用户），不进入无限修复循环。
4. **可关闭**：`script_memory_enabled = false` 时完全降级为每次直接生成脚本，
   不影响其它功能。

**边界与异常**：记忆检索零命中 → 直接走生成路径；记忆后端不可用 → 降级并
日志提示（产品仍可用，见 FR-6 降级）。

**验收标准**：
- [ ] 同一任务第二次执行：`reused_script = true` 事件出现，且 LLM 调用数 ≤ 首次的 30%。
- [ ] 构造一次可复现的失败场景：修复路径恰好触发 1 次 LLM 调用，二次失败后
      以结构化错误收尾（无第三次调用）。
- [ ] `script_memory_enabled=false` 场景下功能全绿，且无任何记忆读写。

### FR-4 下载与文件

**需求描述**：自然语言触发下载，产出文件安全、可预期、不污染用户目录。

**行为规格**：
1. **触发**：指令含下载意图（"下载 xxx"/"保存报表"）时调用 `download`。
2. **文件名智能推断**：优先取 `Content-Disposition`/URL 末段，均不可得时按
   上下文生成有语义文件名。
3. **路径安全**：文件名参与路径拼接时经双规范化校验，防路径穿越
   （`..`、绝对路径、空名一律拒绝并归入合法名）。
4. **同名处理**：已存在同名文件自动追加 `-N` 后缀（`report-1.pdf`、`report-2.pdf`…），
   绝不覆盖现有文件。
5. **默认目录**：`./downloads`（可配置，见 §7）。

**边界与异常**：下载目标为 0 字节/失败重试/网络中断 → 结构化错误按 FR-2 呈现，
不留半截文件占用原路径。

**验收标准**：
- [ ] 穿越payload 集（`../x`、`/etc/passwd`、绝对路径、空串、`..\\x`）注入文件名推导，产出路径全部落在 downloads 目录内 = 0 例越界。
- [ ] 同名 3 连下载产生 `a.pdf / a-1.pdf / a-2.pdf`，原文件均未被覆盖。
- [ ] 未指定目录时的默认落点 = `./downloads`（相对启动目录）。

### FR-5 会话持久化与恢复

**需求描述**：会话不丢——崩溃/重启后从最后完整步骤续跑（支持主张③）。

**行为规格**：
1. **转录落盘**：全量会话转录以 JSONL 追加写入 `~/.webai/sessions/`；
   写后即 flush（架构定论五），崩溃最多损失最后一条截断记录。
2. **恢复**：启动/`session/resume` 时扫描 `~/.webai/sessions/*.jsonl`，
   丢弃最后一条非法/截断行，重建转录，从最后一个**完整** step 的位置续跑。
3. **可查**：用户可列出并查看历史会话转录。

**边界与异常**：无历史会话 → 新会话路径；历史转录被手工改坏（非法 JSON）→
跳过坏行而非整体失败。

**验收标准**：
- [ ] 崩溃恢复成功率：模拟 kill -9 于任意步骤点，重启后 100% 可从最后完整步骤继续（§6 健壮性 100%）。
- [ ] 截断 fuzz：人工截断/篡改第 k 条记录，恢复后转录不含任何非法行且不整体失败。

### FR-6 记忆与知识

**需求描述**：长期记忆双通道（语义 + 关系），跨会话召回回写，且允许降级
运行（支撑主张②的跨会话复用基础）。

**行为规格**：
1. **双通道**：
   - 向量通道：语义相似检索（HNSW）——回答"意思相近的任务"。
   - 图通道：实体/关系（Kuzu 图）——回答"与某实体/域名相关的操作"。
2. **召回回写**：跨会话可召回（前置会话学到的脚本/知识带回来），新学习内容
   在会话收敛时回写。
3. **降级**：记忆后端不可用 → 该会话自动降级为"无记忆"运行并打日志，
   产品主流程（FR-1/2/4/5）不受影响；后端恢复后新会话自动复用。

**边界与异常**：向量模型缺失 → 仅图通道可用或整体降级，均不允许打断当前任务。

**验收标准**：
- [ ] 跨会话召回：会话 A 学会"导出新浪报表"脚本；会话 B 同语义请求能召回（`reused_script=true`）。
- [ ] 后端不可用注入（停掉 mem 服务）：主流程用例全绿，日志含明确降级记录。

### FR-7 LLM 灵活配置

**需求描述**：模型接入不绑定单一厂商——云上 OpenAI 兼容 API 或本地
llama.cpp 均可，一次配置全局生效。

**行为规格**：
1. **多 provider**：支持 OpenAI 兼容 API 与本地 llama.cpp（OpenAI 兼容本地
   端点亦可）两类 provider。
2. **profile 方案**：以命名 profile 存储配置（§7 `llm.toml`），按名称选择，
   `ctk`/切换无需改代码。
3. **全局生效**：配置读取一次，TUI/ACP/`--serve` 三形态共用同一 LLM profile。

**边界与异常**：profile 不存在/鉴权失败 → fail-fast 启动报错并指明 profile；
不允许静默回退到默认 key 造成意外计费。

**验收标准**：
- [ ] 两个 provider profile（云 + 本地）各走一遍 FR-1 冒烟用例，行为一致、无代码改动。
- [ ] 非法 profile 名：启动即结构化报错且不产生任何 LLM 调用。

### FR-8 安全与可控

**需求描述**：产品"能干必要的事"，同时把越权、死循环、资源失控的成本护栏
做足。

**行为规格**：
1. **文件工具沙箱**：filesystem/memory 相关工具对非授权路径（跨出配置允许目录、
   系统敏感路径）一律拒绝，路径必须规范化后校验。
2. **循环守卫**（成本护栏）：
   - `max_steps = 30`（默认）：单回合步数超限即停并报告，防失控烧 token。
   - **重复观察熔断**：连续 2 次相同 observation → 判定"点了没反应"，立刻
     停止并报告，防止死循环。
3. **网络边界**：服务模式默认仅绑定 `127.0.0.1`；`--public` 显式开启公网并
   必须启用配对认证（§3.3）。
4. **配置护栏**：`max_steps` / `duplicate_threshold` 等关键护栏可在 §7 配置
   调整，但**不可通过自然语言指令关闭**（用户话术不得绕过护栏）。

**边界与异常**：触顶行为必须报告为结构化错误（错误码 + 已执行步数 + 原因），
不得静默截断。

**验收标准**：
- [ ] 沙箱逃逸payload 集（绝对路径、`..`、symlink 指向外部）注入文件工具，越界操作 0 例。
- [ ] 构造 31 步任务 → 第 30 步后停止并返回 `max_steps_exceeded` + 已执行真实步数。
- [ ] 构造"点击无效元素"场景 → 连续 2 次相同 observation 后触发 `duplicate_observation` 熔断，前后无第 3 次重复动作。
- [ ] 绑定校验：未 `--public` 时，非 loopback 源连接被拒；`--public` 但未配对时请求被拒。

## 5. 用户体验蓝图（关键旅程）

> 4 条旅程 = 4 条可演示剧本（demo script）。每条给出**可执行的 UI 文案或协议
> 事件示例**，验收时据此核对（与 §6 指标、架构测试金字塔端到端层配合）。

### 旅程 A：首次使用（本地 TUI 主路径）

目标：新用户 30 秒内理解"对着浏览器说话"这一心智模型。

演示剧本：
```
$ webai
┌ AI 浏览器 ────────────────────────────────────────┐
│ 你: 打开新浪财经，汇总今天头条                      │
│ ├─ 思考 · 用户要的是头条汇总，先导航到新浪财经首页   │
│ ├─ 操作 · navigate https://finance.sina.com.cn      │
│ ├─ 观察 · 页面已加载，标题"新浪财经_新浪网"  [截图] │
│ ├─ 思考 · 找到今日头条区块，抽取 10 条              │
│ ├─ 操作 · get_text → #headline-list                 │
│ ├─ 观察 · 已取得 10 条头条文本          [截图]      │
│ └─ 完成 · 今日头条汇总（10 条，含链接）             │
└────────────────────────────────────────────────────┘
```

验收核对点：
- 首次使用无需任何配置（默认 LLM profile 开箱即用，见 §7）。
- 每步三元组（思考/操作/观察）流式逐行出现，不"等全部完成再显示"。
- 关键动作后自动附带截图（主张③：可核对）。
- 交互约定全部生效（Enter/↑↓/PgUp/PgDn/Esc/Ctrl+C，见 §3.1）。

### 旅程 B：重复任务加速

目标：证主张②——第二次起明显更快，且有明确"复用了记忆"的标识。

演示剧本（同一用户第二次输入相同请求）：
```
你: 打开新浪财经，汇总今天头条
├─ 操作 · [复用记忆脚本 navigate→extract]（历史 2 次成功，上次 2026-08-30）
│         replay 参数：url=https://finance.sina.com.cn
├─ 观察 · 列表就绪（复用校验通过，无需 LLM 推理）     [截图]
└─ 完成 · 今日头条汇总（10 条，含链接）
        · 标记：本次复用记忆脚本，LLM 调用 1 次（首次为 6 次）
```

验收核对点（对应 §6 效率指标）：
- 界面显式出现 `[复用记忆脚本 ...]` 标记（TUI）或事件 `reused_script=true`
  （ACP），二者不可缺失。
- 耗时口径：第二次完成时间 ≤ 首次的 30% 预算（LLM 调用次数为铁证）。

### 旅程 C：失败自愈

目标：证 FR-3 的修复路径——失败可见、原因可归因、一次修复、记忆更新。
不允许出现"不明原因失败"。

演示剧本：
```
你: 打开 github 热议页面，把 star 前十点开看 README
├─ 操作 · navigate github.com/trending
├─ 观察 · 页面已加载                            [截图]
├─ 操作 · click → a:contains("repo-abc")        ← 目标选择器
├─ 观察 · ✗ verify 失败：execute 成功但 verify 检测到页面 URL 未变化
│         JS 异常: expected URL to contain "repo-abc", got
│                  "https://github.com/trending"
├─ 状态 · 修复中（第 1/1 次）：基于新页面状态重写选择器…
├─ 操作 · click → article h2 a:nth-of-type(1)
├─ 观察 · ✓ verify 通过：URL = /repo-abc          [截图]
└─ 完成 · 已打开 repo-abc README；本次修复已更新记忆脚本
```

验收核对点（对应 §6 可诊断指标）：
- 失败信息带阶段（execute/verify）+ JS 异常原文，无 unknown error。
- 修复恰好一次；成功入库 + 记忆更新事件可见；失败则结构化收尾（FR-3）。

### 旅程 D：脚本接入（ACP）

目标：证形态二/三——宿主程序化调用浏览器能力，拿到流式事件。

协议事件示例（`webai --serve`，宿主为 jcode 插件）：

```json
→ {"jsonrpc":"2.0","id":1,"method":"session/new","params":{}}
← {"jsonrpc":"2.0","id":1,"result":{"sessionId":"s-3f89x1"}}

→ {"jsonrpc":"2.0","id":2,"method":"session/prompt",
   "params":{"sessionId":"s-3f89x1",
             "prompt":"把当前页面标题和前 3 条要点发给我"}}
← 流式事件：
   {"method":"session/event","params":{"event":"step","thought":"先读取标题…",
     "tool":{"verb":"get_title"},"observation":"…","image":"data:image/png;base64,…"}}
   {"method":"session/event","params":{"event":"step","reused_script":true,…}}
   {"method":"session/event","params":{"event":"done","result":"…3 条要点…"}}

→ {"jsonrpc":"2.0","id":3,"method":"session/close","params":{"sessionId":"s-3f89x1"}}
← {"jsonrpc":"2.0","id":3,"result":{"ok":true}}
```

验收核对点（对应 §3.2/§3.3）：
- `session/new → prompt* → close` 生命周期严格成立，每会话隔离。
- 事件面固定为 `Step/Done/Error`（含 `reused_script`、`image` 字段），宿主
  不解析聊天文案即可驱动 UI。
- 绑 127.0.0.1 默认安全（非 loopback 拒绝），公网需显式 + 配对（§3.3）。

## 6. 产品指标与验收标准

> 本节把 §1-5 的承诺变为**可量化、可测、有数据来源**的指标。每条指标给出：
> 定义 / 测量方式 / 数据来源 / 目标阈值 / 关联需求。验收口径以本节为准，
> 与架构测试金字塔（端到端层 + 会话持久化层）配合。

### M-1 正确性：标准操作用例矩阵通过率

- **定义**：在标准浏览器操作测试用例集（`browser-operation-test-cases`，
  13 动词 × 典型页面元素 × 登录态/JS 重渲染/验证码前置等真实环境变体）中，
  用例完全成功（execute+verify 双通过且产物正确）的比例。
- **测量方式**：端到端测试按用例矩阵逐条执行，统计
  `通过数 / 总数 × 100%`；每条用例必须给出"输入指令 + 预期产物 + 校验断言"。
- **数据来源**：`browser-operation-test-cases` 用例矩阵 + 端到端测试报告。
- **阈值**：≥95%（v0.4 验收）；未达标的用例必须逐条登记在案并附原因。
- **关联需求**：FR-1/FR-2/FR-4；主张①。

### M-2 效率：重复任务记忆命中成本

- **定义**：同一任务第二次执行相较首次，LLM 调用次数比
  `第二次 LLM 调用数 / 首次 LLM 调用数 × 100%`（记忆命中场景）。
- **测量方式**：会话转录中取 `reused_script=true` 的事件与前后 LLM 调用计数
  求比值；统计口径包含 planning 与 repair 调用；采样 ≥30 个不同任务。
- **数据来源**：`SessionEvent`（含 `reused_script`）+ LLM 调用日志
  （每次调用记一行）。
- **阈值**：≤30%（对应主张②"越用越快"）；波动分析以中位数而非均值。
- **关联需求**：FR-3/FR-6；旅程 B。

### M-3 健壮性：崩溃后会话恢复成功率

- **定义**：任意运行点被强制终止（kill -9 / 断电 / panic）后，从
  `~/.webai/sessions/<s>.jsonl` 重建会话并**从最后完整 step 续跑成功**的比例。
- **测量方式**：自动化注入崩溃（多阶段 kill -9），重启执行
  `session/resume`（或 TUI 重开），断言"转录恢复 + 续跑产出正确"。
- **数据来源**：会话 JSONL + 恢复日志 + 端到端断言。
- **阈值**：100%（可恢复会话）= 不允许"看起来能跑但转录错乱"；截断/篡改
  最后一条时跳过坏行仍成功（FR-5 验收）。
- **关联需求**：FR-5；主张③。

### M-4 可诊断：失败调用结构化占比

- **定义**：全量失败调用中，携带结构化错误（阶段 `execute|verify` + JS 异常
  原文 + `error.code`）的占比。
- **测量方式**：对错误日志全量审计，统计 "含 phase 与 error.code 与异常原文
  的失败 / 总失败"；`unknown error`/`未知错误`/空串 error.code 计为不合格。
- **数据来源**：错误日志 + 协议层 error 事件。
- **阈值**：100%（零 unknown error）——任何吞错都视为 release blocker。
- **关联需求**：FR-2/FR-3/FR-8；旅程 C。

### M-5 安全：路径穿越 / 覆盖已有文件

- **定义**：文件与下载类操作中，路径逃逸（绝对路径/`..`/symlink 指向沙箱外）
  与覆盖既有文件的发生次数。
- **测量方式**：穿越 payload 集与同名冲突用例注入（FR-4/FR-8 验收），统计
  越界与覆盖发生次数；同时做静态审计（路径拼接处必经校验函数）。
- **数据来源**：文件工具单测 + 端到端下载用例 + 代码走查。
- **阈值**：0 例。任何 1 例即阻断发布。
- **关联需求**：FR-4/FR-8。

### M-6 资源：单会话空闲内存

- **定义**：单会话空闲（等待输入）时进程常驻内存，不计 LLM 侧（远端 API
  无进程；本地 llama.cpp 单独进程独立计量）。
- **测量方式**：`RSS` 采样（每 5s，取空闲稳定后均值）；条件 = 1 个会话 +
  1 个 WebKit 视图已加载典型页面；不含 LLM 进程。
- **数据来源**：`/proc/<pid>/status` / `pmap` 采样脚本 + CI 性能 job。
- **阈值**：< 300MB（不含 LLM）。
- **关联需求**：FR-8 资源护栏；自动化运维场景（定时长驻）。

### M-7 用例矩阵 ↔ 度量映射（验收总表）

| 指标 | 阈值 | 数据来源 | 验收关卡 |
|---|---|---|---|
| M-1 用例矩阵通过率 | ≥95% | test-cases + e2e | v0.4→release |
| M-2 记忆命中成本 | ≤30% LLM 调用 | SessionEvent + LLM 日志 | v0.2 起持续 |
| M-3 恢复成功率 | 100% | JSONL + resume 断言 | v0.3 起持续 |
| M-4 结构化失败占比 | 100% | 错误日志审计 | release blocker |
| M-5 穿越/覆盖 | 0 例 | 单测 + 走查 | release blocker |
| M-6 空闲内存 | <300MB | RSS 采样 | v0.4 性能门 |

## 7. 配置即产品（面向部署者的界面）

> 原则：**默认值开箱即用，全部可关，改坏一个文件不影响其余**。配置决定
> 部署者的操作界面——不写代码也能调产品行为与成本面。

### 7.1 五文件 TOML schema

| 文件 | 职责 | 关键键 | 缺失影响 |
|---|---|---|---|
| `agent.toml` | agent 行为 | `max_steps`、`duplicate_threshold`、`auto_plan_on_multi_step`、`script_memory_enabled` | fail-fast（无默认行为护栏时拒绝启动） |
| `llm.toml` | LLM provider | 多 profile（`[profile.xxx]`：endpoint / model / api_key / timeout） | fail-fast，按名选 profile |
| `embd.toml` | 向量 embedding | 本地/远程模型端点、维度 | 降级：仅图通道或无记忆运行 |
| `mem.toml` | 记忆储存 | 向量+图后端地址、数据库路径 | 降级：无记忆运行，主流程不受影响 |
| `vec.toml` | 向量检索 | HNSW 参数（M/ef/维度）、索引路径 | 降级：同 embd |

覆盖机制：`WEBAI_CONFIG` 环境变量指向配置目录，未设置时使用默认位置
（`~/.webai/config/`）。单文件损坏 = 仅该文件维度受影响（`llm.toml`/`agent.toml`
例外：无值时 fail-fast，避免无护栏运行）。

### 7.2 关键开关清单

| 开关 | 默认 | 作用 | 对应需求 |
|---|---|---|---|
| `max_steps` | 30 | 单回合步数上限（循环守卫） | FR-8 |
| `duplicate_threshold` | 2 | 连续相同观察熔断阈值 | FR-8 |
| `auto_plan_on_multi_step` | true | ≥2 动词/连接词自动 create_plan | FR-1 |
| `script_memory_enabled` | true | 脚本记忆复用开关 | FR-3 |
| `downloads_dir` | `./downloads` | 下载默认目录 | FR-4 |
| `sessions_dir` | `~/.webai/sessions/` | JSONL 会话落盘目录 | FR-5 |
| 绑定地址 / `public` | `127.0.0.1` / 关 | 服务模式网络边界 | §3.3 |
| 配对认证 | 关（默认本机） | 公网模式强制启用 | §3.3/FR-8 |

约束：`max_steps` / `duplicate_threshold` 等成本护栏**不可经自然语言指令关闭**
（FR-8）；`llm.toml` 只经文件配置，界面不暴露 API key 输入（安全：密钥不进
转录、不进 JSONL）。

### 7.3 配置完整性验收

- [ ] 空目录首启：全默认值可完成旅程 A 冒烟（开箱即用）。
- [ ] 单文件缺失/损坏矩阵：agent/llm fail-fast 报错；embd/mem/vec 降级运行不中断主流程。
- [ ] 修改一个文件不影响其余四个（"改坏一个文件"隔离性验证）。

## 9. 风险与对策

| 风险 | 影响 | 对策 | 验证方式 |
|---|---|---|---|
| WebKit 页面兼容性（反爬/验证码/桌面版 vs 移动版渲染） | 主张①可信度受损 | 真浏览器引擎 + 登录态会话维护；产品层明示能力边界（§1-2 差异中坦承） | test-cases 矩阵加入登录态/验证码前置/JS 重渲染变体 |
| LLM 写脚本质量不稳定 | 成功率波动 | 两阶段 verify + 一次上下文修复 + 脚本记忆沉淀（FR-3） | M-1 用例通过率 + M-4 结构化失败 |
| token 成本失控 | 运维/用户成本 | 记忆复用 + 历史压缩 summariser + 循环守卫（FR-8）+ 护栏不可话术关闭 | M-2 调用数比 + 成本采样 |
| 系统依赖安装门槛（WPE 栈） | 上手难 | 默认 stub 构建可测试可用；一键安装脚本文档化；长期容器镜像（架构 §11） | stub 下跑通旅程 A 冒烟 |
| 远程接入安全风险 | 被恶意利用 | 默认仅本机绑定；公网显式开启 + 必须配对（FR-8/§3.3） | M-5 安全用例 + 网络边界测试 |

风险登记准则：新风险一经识别即入表并配"对策 + 验证方式"，不允许只列不验。

## 10. 术语表

- **动词（verb）**：浏览器操作的最小单位，映射一个两阶段 JS 脚本（FR-1/架构定论一）。
- **两阶段脚本**：`execute`（做动作）+ `verify`（验后置条件）的函数对；
  失败由此可归因（FR-2）。
- **脚本记忆**：成功脚本的结构化存储（`task/verb/url/script`）与回放机制（FR-3）。
- **ACP**：Agent Communication Protocol，JSON-RPC 智能体接入协议
  （over WebSocket / 行分隔 TCP），产品形态二/三的协议基座。
- **状态块**：每回合注入的实时浏览器上下文（URL / 标题 / readyState / 正文片段），
  保证行动基于真实页面（FR-1）。
- **守卫（guard）**：`max_steps`、`duplicate_threshold` 等成本熔断机制，
  默认开、不可被话术关闭（FR-8/§7.2）。
- **锚点动作**：§1.1 五动作（你说/它看/它做/它证/它学），被 FR 与指标多处置回指，
  是产品心智模型的最小锚点。
